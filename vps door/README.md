# Папка «vps door» — доступ к вашему VPS для другого проекта

Эту папку можно **целиком скопировать** в корень другого репозитория (например, параллельного приложения). В ней **нет секретов**: только шаблоны и инструкции. Реальные пароли и пути к ключу вы храните в локальном файле, который не попадает в git.

## Что сделать один раз после копирования

1. **Создайте файл с доступами** (его не коммитим — он в `.gitignore`):
   - Скопируйте `set-vernatun-ssh-env.EXAMPLE.ps1`
   - Переименуйте копию в **`set-vernatun-ssh-env.local.ps1`**
   - Откройте и впишите:
     - `VERNATUN_SSH_KEY` — полный путь к **приватному** SSH-ключу на вашем ПК (тот же, что используете для входа на сервер)
     - `VERNATUN_SSH_USER` — имя пользователя Linux на VPS
     - `VERNATUN_SSH_HOST` — IP или домен сервера
     - `VERNATUN_REMOTE_BOT_DIR` — **папка на сервере**, куда нужно выкладывать это приложение (для бота «Вернатун» в исходном проекте это каталог с `bot` на VPS; для другого приложения укажите свой путь)

2. **Откуда взять готовые значения**, если вы уже настраивали проект «TG Bot Վերնատուն»:
   - Откройте в том репозитории файл `scripts\set-vernatun-ssh-env.ps1` — там те же четыре переменные `$env:VERNATUN_*`
   - Скопируйте четыре строки присваивания в свой `set-vernatun-ssh-env.local.ps1` в папке «vps door» нового проекта
   - У **`VERNATUN_REMOTE_BOT_DIR`** при необходимости смените путь на каталог **нового** приложения на сервере

## Как пользоваться в терминале Cursor (PowerShell)

Загрузить переменные в **текущую** сессию (важна **точка** и пробел в начале):

```powershell
. ".\vps door\load-ssh-env.ps1"
```

Либо напрямую:

```powershell
. ".\vps door\set-vernatun-ssh-env.local.ps1"
```

После этого команды `ssh` / `scp` с вашим ключом смогут использовать те же данные, что заданы в переменных окружения.

## Как подключить ИИ-агента в другом проекте

Скопируйте содержимое файла **`CURSOR-AGENT-PROMPT.txt`** в правила проекта (например, в `.cursor/rules/…`) или вставьте в системный промпт / первое сообщение чата — там по шагам расписано: сначала `load-ssh-env`, потом проверки, потом `ssh`/`scp`.

## Имена переменных

Они намеренно те же, что в скриптах репозитория Vernatun (`VERNATUN_SSH_KEY`, `VERNATUN_SSH_USER`, `VERNATUN_SSH_HOST`, `VERNATUN_REMOTE_BOT_DIR`), чтобы вы могли **перенести в другой проект** и скрипты `scripts/restart-bot.ps1` / `deploy-bot-to-vps.ps1`, если скопируете их тоже — параметры подхватятся из окружения.

## Безопасность

- Не коммитьте `set-vernatun-ssh-env.local.ps1` и не кладите в репозиторий приватные ключи.
- Файл `Server door.txt` (если он у вас есть в старом проекте) — это заметка для человека; для скриптов используйте именно переменные в `local.ps1`.
