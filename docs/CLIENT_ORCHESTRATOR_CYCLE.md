# Цикл Клиент ↔ Оркестратор (обязательный)

Источник правды для запуска из чата. Короткая команда — в файле `promts` и в `.cursor/prompts/start-client-orchestrator-cycle.md`.
Читать целиком перед стартом. Knowledge — универсальная `knowledge/`, без домена чужого продукта.

Цикл **не завершён**, пока одновременно:

1. все тикеты Клиента `C-*` закрыты с **guard**;
2. Клиент явно написал слово **«согласовано»** в финальном отчёте пользователю.

Роли: **Клиент** и **Оркестратор** (Архитектор → специалисты из реестра → Тестировщик → Фиксер → Деплоер). Контуры не смешивать.

Используй полную библиотеку `.cursor/skills/`, `.cursor/mcp.json`, `plugins/`, `knowledge/`. Новые агенты из `.cursor/registry/agents.md` входят в команду Оркестратора.

---

## Лимиты

| Кто | За один прогон |
|-----|----------------|
| **Клиент** | любое число тикетов `C-*` |
| **Оркестратор** | **максимум 3 тикета** в одной волне, без overlapping paths |

---

## ФАЗА A — КЛИЕНТ

`client.mdc` + client-review / visual-critic / ticket-engine из `.cursor/skills/` + оболочка `knowledge/engineering/roles/client.md`.

1. Смотри живой localhost (не только файлы на диске). Visual — скрины MCP / image-diff.
2. Выдай любое число `C-*` в `memory/tickets/` + `_index.md`.
3. Сразу передай управление Оркестратору. Не останавливайся на списке тикетов.

---

## ФАЗА B — ОРКЕСТРАТОР (волна ≤ 3)

1. `memory/waves/W-*.md`, `before_sha`.
2. Архитектор: spec + `chain.md` **до кода**.
3. Специалисты по chain (Frontend / Motion / WebGL / Backend / новые агенты из реестра).
4. Тестер + guard; Фиксер до зелёного; Деплоер localhost.
5. Закрытие только с guard. Стоп «готов продолжить».

---

## ФАЗА C — ПОВТОР

Снова Клиент. Пока очередь не пуста и нет слова **«согласовано»**.
